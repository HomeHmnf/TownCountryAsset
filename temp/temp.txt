# WDI WP1.5 area and population-density acquisition

**Status:** acquisition and read-only candidate-validation workflow implemented; no live acquisition or semantic approval implied.  
**Dataset:** `wdi_wp1_5_area` (separate from `wdi_selected_macro_indicators`)  
**Fields:** 3, 33 and 34.

## Scope and definitions

| WP1.5 field | WDI indicator | Canonical unit | Definition boundary |
|---:|---|---|---|
| 3 | `EN.POP.DNST` | people/km² | Population density per square kilometre of land area |
| 33 | `AG.SRF.TOTL.K2` | km² | Surface area, including inland water and some coastal waterways |
| 34 | `AG.LND.TOTL.K2` | km² | Land area, excluding inland water |

Do not substitute surface area for land area. Population density is a published WDI measure and is not recomputed from the project's population and area values.

This is a separate rolling API snapshot. It must not be added to or overwrite the historical macro-comparison snapshot. Raw provider responses are local-only; manifests and reports are tracked.

## 1. Capture

Run from the repository root:

```fish
uv run python -m tools.acquire_world_bank_wdi_wp1_5_area capture --start-year 2015 --end-year 2025
```

If the network requires the already configured proxy:

```fish
proxychains uv run python -m tools.acquire_world_bank_wdi_wp1_5_area capture --start-year 2015 --end-year 2025
```

The capture stores WDI source metadata, every page of the country catalogue, metadata for all three indicators, and every observation page. Each response is preserved byte-for-byte with request/final URL, parameters, headers, retrieval timestamp, HTTP status, byte count and SHA-256. Pagination changes, malformed responses, and non-WDI indicator metadata abort capture. Existing timestamped paths are never overwritten.

Output roots:

- Raw: `raw_data/sources/world_bank_wdi/wdi_wp1_5_area/<snapshot_id>/`
- Manifest: `data_manifests/sources/world_bank_wdi/wdi_wp1_5_area/<snapshot_id>.json`
- Acquisition report: `reports/sources/world-bank-wdi-wp1-5-area/<snapshot_id>/`

## 2. Prepare an explicit identity crosswalk

Candidate validation requires a separately reviewed JSON crosswalk. The dataset identifier must be `world_bank_wdi_wp1_5_area`; each mapping's `source_id` is the WDI ISO3 code, and `game_id` is the persistent project identity.

Example shape (illustrative only; not a real mapping):

```json
{
  "schema_version": 1,
  "dataset": "world_bank_wdi_wp1_5_area",
  "source_key": "world_bank_wdi",
  "mappings": [
    {
      "game_id": "tc_00000000000000000000000000000000",
      "source_id": "AAA",
      "match_method": "reviewed_manual",
      "evidence_url": "https://example.org/identity-evidence"
    }
  ]
}
```

Use only explicit authoritative or reviewed mappings. Do not generate mappings by matching country names, by assuming ISO3 equals the registry's ISO field, or by silently dropping territories and disputed entities. Partial crosswalks are permitted; unmapped provider observations remain visible in the candidate CSV and report. The validator checks mapped `game_id` values against `config/country_identity_registry.json`.

## 3. Validate and produce candidates

After capture and crosswalk review, set the exact manifest path:

```fish
set manifest data_manifests/sources/world_bank_wdi/wdi_wp1_5_area/api_snapshot_YYYYMMDDTHHMMSSffffffZ.json
uv run python -m tools.acquire_world_bank_wdi_wp1_5_area validate --manifest $manifest --crosswalk data/manual/source_crosswalks/world_bank_wdi_wp1_5_area.json
```

The validator first verifies every raw artifact's SHA-256 and byte count, source identity, all three indicator bundles, and complete country/observation pagination. It then:

- excludes WDI aggregates using the captured country catalogue's region classification;
- rejects duplicate ISO3/year observation keys and flags invalid, non-finite or out-of-range values;
- retains null-row counts and missing coverage rather than filling values;
- selects the latest non-null observation independently for each indicator and ISO3, retaining the reference year and raw `obs_status`;
- maps ISO3 to `game_id` only through the supplied crosswalk;
- checks surface area against land area only when both selected observations have the same reference year.

Candidate output is written under `reports/sources/world-bank-wdi-wp1-5-area/<snapshot_id>/candidate_validation/`, including `assessment.json`, `assessment.md` and `wdi_wp1_5_area_candidates.csv`.

A blank `obs_status` is not interpreted as actual. Different indicators can have different latest reference years. The same-year surface/land check is a consistency diagnostic, not an assertion that all country areas must match an external geometry dataset.

# Canonical SQLite database architecture

**Status:** WP1.1–WP1.4 implemented and locally validated by the owner. WP1.5 is in progress; schema v3 and candidate source contracts are committed but await owner-side validation. No consumer cutover is included.
**Canonical local path:** `data/canonical/town_country_asset.sqlite`

> **Architecture transition notice (2026-11-05):** This document describes the current, still-active schema and historical implementation. The owner has confirmed a target separation into a game-only database and a project source/research database, with two retained successful source versions per acquisition stream. The target is **not implemented**. See the [data-store separation plan](data-store-separation-plan.md); do not treat the current source-provenance columns/tables as the final game DB contract.
**Schema versioning:** Local database ledger; migration SQL is version-controlled.

## Scope and authority

SQLite is the planned canonical structured store for country identity, source provenance, names, regions, source attributes, geometry profiles, review evidence, selected game data, and current statistics. The database is local application data and is not committed to Git. Existing JSON configuration, registry, generated assets, and pipeline behavior remain in place during the parallel migration.

Persistent `game_id` values remain the internal identity. They are exactly `tc_` followed by 32 lowercase hexadecimal characters. Natural Earth source identifiers and ISO codes are separate attributes. Imported records default to `candidate`. Populated source values are treated as the supplied dataset values unless the owner identifies an error; completeness reporting focuses on empty/null values. Verification is applied after the relevant data domains have been populated, not prematurely during partial imports.

## WP1.1 implementation

- `migrations/001_initial_schema.sql` defines the initial schema.
- `tools/database/connection.py` configures SQLite connections, foreign keys, WAL for file-backed databases, FULL synchronous writes, and a 5-second busy timeout.
- `tools/database/schema.py` applies numbered SQL migrations in order, records applied versions locally, rejects gaps, mismatched migration names, and databases newer than the available code, and rolls back failed migration DDL and ledger writes.
- `tools/migrate_database.py` creates or upgrades the local database and runs SQLite integrity and foreign-key checks.
- The default database path is repository-relative: `data/canonical/town_country_asset.sqlite`. A `--database` override supports isolated testing and alternate local locations.

## Schema v1–v3 table contract

Schema migration 002 upgrades the local database to schema version 2 by adding `countries.entity_type_status` (`unreviewed` or `reviewed`). Schema migration 003 upgrades to version 3 with explicit statistic value status and source-observation metadata. The v1 table inventory below remains the base table contract; later migrations extend it without introducing parallel domain-specific review tables.

| Table | Responsibility |
|---|---|
| `schema_migrations` | Local applied migration version/name/time ledger |
| `dataset_imports` | Dataset provenance, SHA-256, attribution, license, import status |
| `countries` | Stable identity, entity type, record status, ISO values/status, localization status |
| `country_sources` | Current and historical source identifiers by dataset |
| `country_names` | Language-specific canonical names and aliases |
| `country_regions` | Explicit region membership and classification source |
| `country_attributes` | Typed source attributes, including validated JSON values |
| `country_geometries` | Low/medium/high geometry payloads and checksums |
| `import_runs` | Import execution status and source checksum |
| `current_statistics` | One current value per country/statistic key |
| `selected_game_data` | Explicitly selected game-data payloads only |
| `country_flags` | Flag source mapping, review status, decision note and evidence |
| `review_proposals` | Deduplicated ISO/localization/entity/flag proposals and evidence |

The base SQL definitions are authoritative in `migrations/001_initial_schema.sql`; review-domain changes are in `migrations/002_review_domain_status.sql`; WP1.5 statistic provenance changes are in `migrations/003_statistics_provenance.sql`.
